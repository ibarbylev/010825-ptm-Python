## 1. Что такое `unittest`

`unittest` — это **встроенный фреймворк модульного тестирования** в Python  
(аналог JUnit - Java-аналог unittest'ов).

Он позволяет:

* писать автоматические тесты;
* проверять корректность работы функций, классов, модулей;
* запускать тесты пакетно;
* получать отчёты об ошибках.

---

## 2. Основные понятия

### Модульный тест (Unit Test)

Проверяет **минимальную единицу кода**:

* функцию
* метод
* класс

Тесты должны быть:

* **независимыми**
  * (от внешних факторов или других тестов)
* **повторяемыми**
  * (при одинаковых входных данны - ВСЕГДА одинаковый результат)
* **автоматическими**
  * (не требовать от тестировщика доп. действий во время тести, вроде ввода в `input()`)

---

## 3. Структура теста

Тест строится по схеме **AAA**:

1. **Arrange** — подготовка данных
2. **Act** — выполнение тестируемого кода
3. **Assert** — проверка результата

---

## 4. Базовая структура `unittest`

```python
def multiply_2(x):
    return 2 * x


import unittest


class TestMath(unittest.TestCase):

    def test_total_returns_sum_of_added_items(self):
        # Arrange
        x = 2

        # Act
        result = multiply_2(x)

        # Assert
        self.assertEqual(result, 4)


if __name__ == '__main__':
    unittest.main()
```

### Обязательные элементы:

* Класс **наследуется от `unittest.TestCase`**
* Имя тестового метода **начинается с `test_`**
* Проверки выполняются через `assert*`

---

## 5. Основные assert-методы

| Метод                  | Назначение          |
| ---------------------- | ------------------- |
| `assertEqual(a, b)`    | a == b              |
| `assertNotEqual(a, b)` | a ≠ b               |
| `assertTrue(x)`        | x is True           |
| `assertFalse(x)`       | x is False          |
| `assertIs(a, b)`       | a is b              |
| `assertIsNone(x)`      | x is None           |
| `assertIn(a, b)`       | a ∈ b               |
| `assertRaises(Error)`  | проверка исключения |

## 6. Методы подготовки и очистки

### Для каждого теста:

```python
def setUp(self):
    # вызывается перед каждым тестом
    self.data = [1, 2, 3]

def tearDown(self):
    # вызывается после каждого теста
    self.data.clear()
```

### Один раз для класса:

```python
@classmethod
def setUpClass(cls):
    pass

@classmethod
def tearDownClass(cls):
    pass
```

## 7. Запуск тестов

### Через терминал:

```bash
python -m unittest test_file.py
```

### Автопоиск тестов:

```bash
python -m unittest discover
```

## 9. TestCase

`TestCase` — это:

* контейнер для тестов
* набор assert-методов
* управление жизненным циклом теста

Каждый метод `test_*` выполняется **в новом экземпляре класса**.

---

## 10. Хорошие практики

✔️ Один тест — одна проверка  
✔️ Имена тестов должны лаконично (но точно!) описывать цели  
✔️ Не использовать `print()`  
✔️ Не зависеть от порядка выполнения  
❌ Не тестировать сразу много логики
